# IMA Share Sync 0.3.6

Fix article lookup failures when IMA briefly exposes multiple matching list entries, or loads a target after a large scroll changes the scroll range.

- Re-read transient duplicate matches within the existing time limit; open only a unique, strictly matching source key.
- Wait for delayed entries and make at most one position correction using the refreshed scroll range.
- Keep cancellation, persistent-ambiguity rejection and existing SourceId download deduplication. No title-only fallback or first-candidate selection.
- Add candidate identity and scroll diagnostics for future lookup failures.

Validation: the full local check passed, including 730 PowerShell assertions. Three previously failing PDFs were downloaded and their first-page content verified in isolation. Repeating the targeted sync skipped all three with zero download calls; repeating import through the built plugin created no duplicate files or overwrites. These are isolated acceptance results, not a claim that a production vault has been synchronized.

The existing scan-stage directory-list disappearance issue and image-only PDF OCR are outside this fix. Persistent ambiguous entries still fail safely. Windows 10+ and Obsidian 1.11.4+ are required.
