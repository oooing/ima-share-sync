# IMA Share Sync 0.3.4

## Changes

- Reduce main.js from 17,395,378 bytes to under 5,000,000 bytes. Remove the unused standalone Node Markdown runner from the desktop bundle; desktop conversion continues to use the same direct processor.
- Embed the local PDF parser WASM as gzip-compressed binary data. Decode it with desktop Node built-ins; no downloads, dynamic JavaScript decoding, or additional installation files. Tests compare restored bytes with the upstream WASM and exercise real PDF fixtures.
- Add GitHub build-provenance attestations for all three release assets, using a commit-pinned official action. Build failure or attestation failure prevents publishing the release.
- Use existing explicit information-row classes instead of redundant CSS :has() selectors.
- Enforce the 5 MB production bundle budget during every build.

## Verification and boundaries

The isolated npm run check suite covers release metadata, lint, types, production build, JavaScript, PDF, Markdown, PowerShell and WPF checks. PDF tests cover text extraction, scope filters, authored-note protection, incremental skips, invalid input and cancellation. Live IMA synchronization is not part of this release's acceptance evidence.

The Community directory's 0.3.3 review ended with an incomplete automated-review message and no visible Error finding. Official documentation says warnings do not block submissions. These changes address actionable findings; they do not claim to resolve an undisclosed platform failure or guarantee marketplace approval.

Remaining warnings may include filesystem/shell access required for Windows IMA automation, vault enumeration for local statistics, legacy settings-search integration, and scoped CSS !important rules. The minimum supported Obsidian version remains 1.11.4. Settings layout migration is not included in this release.

Known issue: a temporarily unavailable IMA list container can still abort directory scanning with “目录列表在检查过程中消失”. This scanning recovery issue is not fixed here.
